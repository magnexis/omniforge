# Workers

Omniforge workers are small, independently executable processes that implement the Omniforge Protocol.

## Worker Requirements

A worker is only counted as supported when it has:

- a worker manifest
- a launch command
- OFP registration support
- at least one real capability
- tests or verified execution coverage

## Worker Families

### Supervisory

- worker health supervision
- queue resilience
- routing fallback
- restart strategy

### Systems

- process inspection
- native diagnostics
- binary and resource analysis

### Services

- API health
- service reachability
- dependency behavior

### Analysis

- structured incident analysis
- scoring
- clustering
- evidence summarization

### Automation

- process control
- environment repair
- command execution under policy

### Policy

- plan validation
- invariant enforcement
- unsafe mutation rejection

## Current Practical Examples

- `ruby`: rules-based record classification
- `javascript`: record validation
- `go`: statistical summarization
- `rust`: artifact compression
- `prolog`: policy reasoning
- `powershell`: remediation planning
